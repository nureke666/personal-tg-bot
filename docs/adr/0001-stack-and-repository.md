# ADR-0001: Один процесс на aiogram и SQLite, планировщик внутри бота

Date: 2026-10-17
Status: accepted

## Контекст

Реконструкция задним числом, по устройству репозитория. Личный бот одного владельца: задачи с
напоминаниями, отсчёты, финансы, привычки. Нужно, чтобы напоминания приходили вовремя и не терялись
после перезапуска, а запуск и перенос на VPS были одной командой.

## Решение

**Python 3.12 + aiogram 3, зависимости через uv** (`pyproject.toml`, `uv.lock`). Апдейты принимаются
long polling (`bot/__main__.py:main` → `dp.start_polling`), вебхука и публичного адреса нет.

**SQLite одним файлом через aiosqlite** (`bot/db.py:connect`): автокоммит, WAL, миграции — список
`bot/db.py:MIGRATIONS` с номером в `PRAGMA user_version`. Время хранится в UTC, показывается в поясе
из настроек.

**Планировщик в том же процессе** (`bot/services/scheduler.py:run`): раз в `tick_seconds` (30 с)
берёт из БД всё, чему пора сработать. Своего состояния у него нет, поэтому перезапуск ничего не
теряет: пропущенное отправляется один раз на следующем тике.

**Один репозиторий, один пакет `bot/`** со слоями `handlers/` → `views/` / `repo/` / `services/`.
Прод — Docker Compose на VPS, база смонтирована в `./data`.

Отвергнуто:

- **Вопрос владельцу:** какие варианты рассматривались (другой фреймворк, Postgres, внешний
  cron или очередь, вебхук) и почему отказались? Без ответа раздел остаётся пустым.

## Последствия

**Бэкап — это копия одного файла:** бот сам присылает её владельцу (`bot/services/backup.py`).

**Один экземпляр на токен:** второй запущенный бот с тем же токеном перехватывает апдейты, поэтому
локальный запуск при работающем проде запрещён (`AGENTS.md`, «Границы»).

**Напоминания приходят, только пока процесс жив,** с точностью до тика; после простоя — одно
сообщение с пометкой «с опозданием».
