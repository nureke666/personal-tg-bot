# ADR-0002: IT-новости собирает сам бот, по правилам и без LLM

Date: 2026-11-22
Status: accepted

## Контекст

Владелец хочет каждый день узнавать, что нового в IT: инструменты, харнессы, модели, релизы. Нужна
подборка раз в день, вечером в одно время, 10 ссылок. Пересказ не нужен, ссылки он открывает сам.

## Решение

**Новости — ещё одно расписание бота, как утренняя сводка и бэкап.** `news_on`, `news_time` и
`news_next_at` лежат в `settings` и обрабатываются в `bot/services/scheduler.py:news_digests`. Время,
выключение и «Прислать сейчас» живут в общем экране настроек (`bot/views/settings.py:SCHEDULES`).

**Только открытые JSON API без ключей.** `bot/services/news.py:SOURCES`: Hacker News (Algolia: топ и
Show HN), поиск GitHub (новые репозитории по звёздам за неделю), тренды Hugging Face, последние релизы
`REPOS`. Источники опрашиваются параллельно с таймаутом 20 с. Источник, который не ответил, даёт пустой раздел
и не мешает остальным.

**Отбор — правилами.** Внутри раздела порядок задают очки или звёзды, на раздел своя квота
(`bot/services/news.py:QUOTAS`), недобор добирается по порядку разделов. Уже присланные ссылки (адрес без схемы и
`www.`) записываются в `news_sent` и больше не приходят.

Отвергнуто:

- **Отдельный скрипт по крону рядом с ботом.** Это второй процесс со своим состоянием, расписанием и деплоем,
  хотя в боте уже есть планировщик, настройка времени и доставка только владельцу. Кнопки под сообщениями
  скрипта, если они понадобятся, приходили бы основному боту, а тот их не понимает.
- **Облачная задача Claude по расписанию с веб-поиском.** Каждый запуск платный, подборка каждый раз разная, и
  без отдельного хранилища задача не помнит, что уже присылала.
- **Выжимки и отбор через LLM.** Владелец сказал прямо: хватит ссылок, читать будет сам. Без LLM нет платных
  вызовов и ключа API.
- **Reddit (r/LocalLLaMA).** И JSON, и RSS отвечают 403 на запрос без авторизации.
- **Уязвимости (CISA KEV, GitHub Advisories).** Владельцу не интересно: нужны новые инструменты и возможности,
  а не дыры.

## Последствия

**Тик планировщика ждёт сбора, до 20 с.** Обычно раз в день; на это время откладываются остальные напоминания.
Если сбор начнёт тормозить чаще, его надо выносить в фоновую задачу.

**Telegram не принял подборку — повтор через 10 минут** (`bot/services/scheduler.py:NEWS_RETRY`), а не на
следующем тике. Каждый сбор — 8 запросов, 4 из них к релизам GitHub, а без токена GitHub даёт 60 таких запросов в
час с одного IP. При повторе каждые 30 с лимит кончился бы минут за восемь, и раздел релизов опустел бы.

**Подборки собираются по одной** (`bot/services/news.py:LOCK`). Второе нажатие «Прислать сейчас» ждёт первое и
получает следующие 10 ссылок, а не те же.

**Источники, квоты и репозитории меняются в коде** (`SOURCES`, `QUOTAS`, `REPOS`), а не в настройках бота.

**Топ HN бывает не про IT.** Правила не понимают тему. Если таких ссылок станет слишком много, первым делом
стоит урезать квоту `top` в пользу Show HN.

**`news_sent` растёт примерно на 10 строк в день** и не чистится. За год это несколько тысяч коротких строк.
